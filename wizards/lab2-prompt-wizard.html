实验二 · 诉求智能分类系统 · 启动提示词向导

你的任务：把实验一《解决方案框架》里场景 A 的结论，翻译成一段能给 Agent 开跑的启动提示词。
跟着向导一步步填——每步都有提示和参考答案，最后点「生成」，自动拼装成完整提示词。
📌 能力定位：本实验只解决"这是什么"——输入一条客户诉求，输出业务类别和不确定性判断。在实验五 · 综合系统 Agent（进阶） 里，分类是可选辅助能力，不是每条请求的强制第一步；本实验的重点是把它做小、做清楚、做可验证。

实验二 · 工作流

先认识 gstack 八环节

gstack 是 Garry Tan（YC CEO）开源的 AI 开发工作流框架，以 skill 形式安装在 opencode 中，用 /命令 调用。它把一次完整的 AI 开发迭代组织成八个环节的流水线，上一环的产出是下一环的输入，一环都不能跳：

office-hours
要不要做 → spec
死磕边界 → autoplan
决策拍板 → build 施工
做出来 → review
找隐患 → qa
测体验 → ship
收尾 → retro
复盘
🔑 你在每个环节的把关点（人的判断不可替代）
环节Agent 会做什么你的 checkpoint
office-hours追问需求细节，尤其数据、口径、兜底回答它关于数据/口径的问题；确认"值得做"
spec死磕边界：失败模式、No-Go、数据模型、验收口径审查 No-Go 是否具体；验收门槛数字照抄，不许被"优化"
autoplan暴露两可决策，等你拍板真的拍板：转人工阈值、兜底策略、要不要做验证面板
build 施工按 SPEC 实现，每模块冒烟；交付入口 src/handler.py 的 handle_request抽查代码没偏离 No-Go；确认测试集来自数据包、不是 Agent 自己编的
review两遍检查（致命 + 信息），P0-P3 分级确认 P0/P1 修复；API key 没硬编码
qa真实跑核心流程 + 边界输入（空文本 / 超长 / 口语 / 对抗样本）五类都测；准确率达标的数字记进 qa-report
ship版本号 + CHANGELOG + README + commit确认 .env 未入库
retro复盘四点：做得好 / 摩擦 / 未覆盖测试 / 改进行动项摩擦写具体；有可执行的行动项
本实验的关键升级：你不一步步教 Agent 写代码，而是把启动提示词一次交给它，让它按这八环节自己跑，你在每个 checkpoint 把关。八环节的纪律靠下面生成的「驱动指令」焊进它的执行里。
实验二 · 安装 gstack

安装 gstack（动手前先装上）

gstack 以 skill 形式装在 opencode 里，用 /office-hours 这类命令调用；没装好，后面这一步根本调不出来。推荐让 Agent 帮你装。

路线 A：让 Agent 自己装（推荐）
请帮我安装 gstack（Garry Tan 开源的 AI 开发工作流框架）： 1. 网络配置：pip 使用清华镜像源，先执行 pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple 2. 网络配置：GitHub 访问走代理 https://ghfast.top（克隆仓库时 URL 前缀加 https://ghfast.top/） 3. 克隆 https://github.com/garrytan/gstack.git 到用户主目录 4. 运行它的 setup 脚本，host 选 opencode 5. 装完后验证一下 /office-hours /spec /autoplan /review /qa /ship /retro 这些技能 都出现在 ~/.config/opencode/skills/ 下 6. 告诉我安装结果
路线 B：手动安装
git clone https://ghfast.top/https://github.com/garrytan/gstack.git ~/gstack cd ~/gstack && ./setup --host opencode
装完自检：
1. 在 opencode 里输入 /office-hours，能加载出技能就算成功；
2. ~/.config/opencode/skills/ 下应能看到 office-hours／spec／autoplan／review／qa／ship／retro；
3. 装不上或看不到就找讲师——课上可以用数据包 离线兜底包/ 走通链路，不卡在这里。
一句底线：安装命令属于课前准备，不要把安装命令写进启动提示词。
实验二 · 启动提示词怎么组装

九个块：缺一块，Agent 就会自己脑补

数据包 脚手架/启动提示词-模板.md 把一份好的启动信息拆成 9 个块，一块都不许留白（其中 3 块有现成写法，自动带入）。每一步都给出确定的内容，不是留白让 Agent 猜。

#要包含的块在本向导里
1背景步骤 1：你是谁、在给谁做、谁拍板（从实验一《解决方案框架》顺延）
2要做什么步骤 2：一句可验收的话（边界一句话：本次不做什么）
3输入输出步骤 3：输入什么、输出什么（类别 ＋ 字段）
4技术选型步骤 4：选什么、为什么不用更复杂的（含理由）
5数据现状步骤 5：无历史标注 → 零样本（含样本纪律）
6测试集自动带入：25 条 ＋ 表头整段写进提示词，Agent 施工前落盘为 CSV
7验收口径步骤 6：三组门槛数字写死
8约束步骤 7：红线一句话 ＋ 边界一句话
9环境与网络自动带入：pip 清华镜像源 ＋ GitHub ghfast 代理
⚠️ 最容易翻车的两条：第 4 项——不写"无历史标注数据"，Agent 可能默认去搭传统机器学习（需要上千条标注），那是死路；第 6 项——不写"转人工不算错"，Agent 会把转人工的样本算成错，跟"拿不准转人工"的设计自相矛盾。
🔒 样本纪律（岭湾口径）：数据由数据包外部给定、连数据一起写进提示词，Agent 施工前落盘为 CSV；数据原样使用，不得改动、不得重造。由数据包外部给定，提示词里连数据一起给——25 条样本（含表头）原样写进去，让 Agent 施工前落盘为 tests/classify_cases.csv。数据一个字都不许改、不许只挑好做的；改了样本＝换了考卷，验收结论作废。
🚧 不写进提示词的东西：完整 No-Go 清单、AGENTS.md 硬约束摘抄、验收命令、逐环节落盘位置长链属于手册与 spec 环节，由 spec 负责产出、由手册负责自查。提示词里只留"边界一句话：本次不做什么"。

实验二 · 驱动指令

驱动指令版：怎么让 Agent 按流程跑

光有启动提示词不够——Agent 默认只理解"你要什么"，不理解"你要它按什么纪律走"。需要一段驱动指令（数据包 脚手架/启动提示词-模板.md 第三节的 5 条，每条一行），把八环节的流程纪律焊进它的执行里。你写好启动提示词后，把两者合起来交给 Agent：

/office-hours 我是一名 FDE 团队（Delta 角色），需要启动岭湾电力客户服务平台场景 A 的施工。 【在这里粘贴你写好的启动提示词，包括 7 个短块：背景 / 要做什么 / 技术选型 / 数据现状 / 测试集 / 验收口径 / 约束】 1. 依次走完 8 个环节：office-hours → spec → autoplan → 施工 → review → qa → ship → retro，不跳步、不简化。 2. 每个环节都要产出对应文件并落盘当前目录，在回复中列出文件名与位置。 3. 走完一环、进入下一环之前先停下来向我汇报，等我确认后再继续（禁止一口气跑完）。 4. 拍板点（验收口径／门槛／兜底）列出选项与利弊并给出建议，最终由我拍板；拍板结论写回 SPEC。 5. 现在从 office-hours 开始。
重点看驱动 3、4："一环一停"和"拍板点列选项等你选"——这两条决定了你后面还有没有把关的机会。没有它们，Agent 可能一口气跑完八环，你失去所有中途纠偏的机会。
